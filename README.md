# SORB

Сервис бронирования общих ресурсов: помещений, оборудования, специалистов и спецзон.

Сейчас проект содержит стартовую страницу с проверкой соединения с API, серверные
проверки состояния и начальную модель пользователя с ролями. Авторизация, каталог
ресурсов, календарь, бронирования и уведомления пока не реализованы.

## Стек и структура

| Часть | Инструменты |
| --- | --- |
| Frontend | React 19, Vite 8, TypeScript 6, Tailwind CSS 4 |
| Состояние и запросы | TanStack Query, Axios, React Router, date-fns |
| Backend | Node.js, Hono 4, TypeScript, Zod/OpenAPI |
| База данных | PostgreSQL 17, Prisma 7, адаптер `pg` |
| Инфраструктура | Docker Compose, npm workspaces |

Для будущей авторизации установлен bcryptjs; JWT-инструменты доступны в Hono.
Для запуска на Node.js используется `@hono/node-server`.

```text
SORB/
├── backend/
│   ├── prisma/             # Схема базы и сохраненные миграции
│   ├── scripts/            # Проверка подключения к базе
│   ├── src/                # Исходники API
│   ├── .env.example        # Пример настроек API
│   └── Dockerfile
├── frontend/
│   ├── src/                # Исходники веб-приложения
│   ├── .env.example        # Пример настроек клиента
│   └── Dockerfile
├── docker-compose.yml
├── package.json            # Общие команды и npm workspaces
└── package-lock.json       # Зафиксированные версии зависимостей
```

## Выбор способа запуска

| Способ | Что работает в Docker | Когда использовать |
| --- | --- | --- |
| Разработка | Только PostgreSQL; API и frontend запускаются через npm | Для изменения кода с автоматической перезагрузкой |
| Полностью в Docker | PostgreSQL, API и nginx со сборкой frontend | Для запуска всей системы без установки Node.js на компьютер |

Для разработки следуйте разделу «Первый запуск для разработки». Для второго
способа после установки Git и Docker перейдите к разделу «Полный запуск через Docker».
Не запускайте оба способа одновременно: они используют одни и те же порты API и frontend.

## Установка необходимых программ

Инструкция ниже рассчитана на Windows и PowerShell. Для первого скачивания
пакетов npm и образов Docker требуется доступ к интернету.

### 1. Git

Установите [Git for Windows](https://git-scm.com/downloads/win).
Он нужен для клонирования и обновления репозитория. Если исходники уже скачаны,
можно использовать имеющуюся папку проекта.

### 2. Node.js и npm

Для локальной разработки установите [Node.js](https://nodejs.org/en/download)
версии **22.12 или новее в ветке 22**, либо **24 LTS**. npm входит в установку Node.js.
Поддерживаемые версии закреплены в `package.json`; файл `.nvmrc` указывает ветку 22.
Глобально устанавливать Vite, TypeScript или Prisma не нужно.

Если запускаете всю систему через Docker, этот шаг можно пропустить.

### 3. Docker Desktop

Установите [Docker Desktop для Windows](https://docs.docker.com/desktop/setup/install/windows-install/).
При необходимости выполните предлагаемые установщиком шаги настройки WSL 2
и перезагрузите компьютер. Запустите Docker Desktop и дождитесь готовности движка.
Проект использует **Linux-контейнеры**. PostgreSQL отдельно устанавливать не нужно.

### 4. Проверка инструментов

После установки откройте новое окно PowerShell, чтобы обновилась переменная `PATH`:

```powershell
git --version
node --version
npm --version
docker --version
docker compose version
docker info
```

Каждая команда должна завершиться без ошибки. Для полностью контейнерного запуска
проверки `node` и `npm` можно пропустить. Команда `docker info` проверяет работающий
движок, а не только наличие программы Docker на компьютере.

## Первый запуск для разработки

### 1. Получите исходники и перейдите в корень проекта

Если репозиторий еще не скачан, скопируйте его адрес из GitHub:

```powershell
# Замените АДРЕС_РЕПОЗИТОРИЯ на настоящий URL репозитория SORB.
git clone АДРЕС_РЕПОЗИТОРИЯ SORB
Set-Location SORB
```

Если проект уже находится на этом компьютере в рабочей папке:

```powershell
Set-Location O:\Github\SORB
```

Для другой папки укажите свой путь. Все дальнейшие команды, если явно не указано
иное, выполняются **из корня SORB**, где находятся `package.json` и `docker-compose.yml`.

### 2. Создайте файлы окружения

```powershell
if (-not (Test-Path backend/.env)) {
    Copy-Item backend/.env.example backend/.env
}
if (-not (Test-Path frontend/.env)) {
    Copy-Item frontend/.env.example frontend/.env
}
```

Эти команды создают только отсутствующие файлы и сохраняют уже введенные настройки.
Значения из примеров подходят для локального запуска без изменений.
Файлы `.env` исключены из Git и на другом компьютере создаются заново.

**Создайте `backend/.env` до установки зависимостей:** во время установки
автоматически запускается генерация Prisma Client, которая читает `DATABASE_URL`.

### 3. Установите зависимости

```powershell
npm ci
```

Команда устанавливает зависимости backend и frontend по общему `package-lock.json`
и автоматически генерирует Prisma Client. Отдельная установка в каждой подпапке
не требуется. Дождитесь успешного завершения команды, прежде чем продолжать.

Для первой установки и после получения изменений используйте `npm ci`.
`npm install` нужен при намеренном добавлении или изменении зависимостей.

### 4. Запустите PostgreSQL

Убедитесь, что Docker Desktop работает, затем выполните:

```powershell
npm run db:up
```

При первом запуске Docker скачает образ `postgres:17-alpine`. Команда запускает
контейнер базы в фоне и ждет его готовности. Проверить состояние можно так:

```powershell
docker compose ps
```

Контейнер `db` должен быть запущен и иметь состояние `healthy`.

### 5. Примените миграции

```powershell
npm run db:deploy
```

Команда создает таблицы по сохраненным миграциям. Она также применяется при
обновлении проекта и не удаляет базу для повторного создания.
Для обычной установки не нужно создавать новую миграцию через `db:migrate`.

Проверьте подключение и наличие таблицы пользователей:

```powershell
npm run db:check -w backend
```

Ожидаемый результат:

```text
PostgreSQL connection: OK
Users table: OK (0 rows)
```

Количество строк может отличаться, если база уже использовалась.
Начальная миграция не создает учетных записей; готовых логина и пароля для входа нет.

### 6. Запустите API и frontend

```powershell
npm run dev
```

Команда запускает оба процесса в одном терминале. Оставьте его открытым:
закрытие терминала или `Ctrl+C` останавливает приложение. Изменения исходников
автоматически подхватываются Vite и режимом наблюдения Node.js.

Откройте [http://localhost:5173](http://localhost:5173).
На стартовой странице должно появиться сообщение `API: соединение установлено`.

| Сервис | Адрес | Назначение |
| --- | --- | --- |
| Frontend | [http://localhost:5173](http://localhost:5173) | Веб-приложение |
| API health | [http://localhost:3000/health](http://localhost:3000/health) | Проверка работающего API |
| API ready | [http://localhost:3000/ready](http://localhost:3000/ready) | Проверка подключения API к PostgreSQL |
| Swagger UI | [http://localhost:3000/swagger](http://localhost:3000/swagger) | Интерактивная документация API |
| OpenAPI | [http://localhost:3000/openapi.json](http://localhost:3000/openapi.json) | Машиночитаемое описание API |
| PostgreSQL | `localhost:5433` | Подключение из локальных инструментов |

В другом окне PowerShell можно проверить API:

```powershell
Invoke-RestMethod http://localhost:3000/health
Invoke-RestMethod http://localhost:3000/ready
```

Ожидаемые ответы: `status: ok`, `service: sorb-api` у `/health`
и `status: ok`, `database: connected` у `/ready`.
`/health` работает без базы; `/ready` возвращает HTTP 503, если подключиться к базе не удалось.

### Запуск процессов по отдельности

При необходимости используйте два окна PowerShell, оба из корня SORB:

```powershell
# Первое окно — API.
npm run dev -w backend
```

```powershell
# Второе окно — frontend.
npm run dev -w frontend
```

Не запускайте эти процессы дополнительно к уже работающей общей команде `npm run dev`.

## Повторный запуск и остановка

При повторном запуске переустанавливать зависимости и копировать `.env` не нужно:

```powershell
Set-Location O:\Github\SORB
npm run db:up
npm run dev
```

Чтобы остановить API и frontend, нажмите `Ctrl+C` в терминале с `npm run dev`.
Чтобы остановить контейнеры, затем выполните:

```powershell
npm run db:down
```

Данные PostgreSQL сохраняются в Docker volume `sorb_sorb_db` и остаются доступными
при следующем запуске. Для полной контейнерной конфигурации используйте
`npm run docker:down` или соответствующую команду из следующего раздела.

## Настройка переменных окружения

### Backend — `backend/.env`

| Переменная | Значение по умолчанию в примере | Назначение |
| --- | --- | --- |
| `NODE_ENV` | `development` | Режим приложения |
| `HOST` | `127.0.0.1` | Адрес, на котором слушает API |
| `PORT` | `3000` | Порт API |
| `CORS_ORIGIN` | `http://localhost:5173` | Разрешенный origin frontend |
| `DATABASE_URL` | `postgresql://sorb:sorb_dev@localhost:5433/sorb?schema=public` | Подключение Prisma к PostgreSQL |

Локальная база из Compose: имя `sorb`, пользователь `sorb`, пароль `sorb_dev`.
Порт 5433 выбран для совместимости с другими локальными проектами.
Эти учетные данные предназначены для локальной разработки.

### Frontend — `frontend/.env`

| Переменная | Значение в примере | Назначение |
| --- | --- | --- |
| `VITE_API_URL` | `http://localhost:3000` | Адрес API для браузера |

После изменения любого `.env` остановите и снова запустите процессы разработки.
Для сборки frontend переменные `VITE_*` подставляются во время сборки;
не помещайте в них секреты, поскольку они доступны в браузере.

Если меняете порт API, измените также `VITE_API_URL`. Если меняете адрес frontend,
обновите `CORS_ORIGIN`. `http://localhost:5173` и `http://127.0.0.1:5173` — разные
origin; для текущей настройки открывайте приложение через `localhost`.

## Полный запуск через Docker

В этом режиме Node.js и npm на компьютере не нужны: зависимости устанавливаются
внутри образов. Нужны исходники проекта, Docker Desktop и доступ к интернету
для первой сборки. Локальные файлы `.env` для этого режима не обязательны:
настройки контейнеров заданы в `docker-compose.yml`.

Остановите локальный `npm run dev`, перейдите в корень репозитория и выполните:

```powershell
docker compose --profile app up -d --build --wait
```

Команда собирает API и frontend, запускает PostgreSQL и ждет готовности сервисов
с настроенными проверками состояния. Во время запуска API сохраненные миграции
применяются автоматически. Frontend обслуживает nginx; изменения исходников
попадут в приложение после повторной сборки этой же командой.

Проверка состояния и просмотр логов:

```powershell
docker compose --profile app ps
docker compose --profile app logs -f backend frontend
```

`Ctrl+C` завершает просмотр логов, сохраняя работающие контейнеры.
Адреса приложения и API остаются прежними: `localhost:5173` и `localhost:3000`.
Внутри Docker API подключается к базе по `db:5432`; с компьютера база доступна
по `localhost:5433`.

Остановка с сохранением данных:

```powershell
docker compose --profile app down
```

Если npm установлен, для запуска и остановки можно использовать сокращения:

```powershell
npm run docker:up
npm run docker:down
```

Настройки локальных `.env` не переопределяют контейнерную конфигурацию автоматически.
Для изменения портов и настроек контейнеров редактируйте `docker-compose.yml`;
адрес API в сборке frontend задается через `build.args.VITE_API_URL`.
Compose-конфигурация предназначена для локального запуска и требует отдельной
настройки секретов, доступа и HTTPS перед публичным развертыванием.

## Работа с базой данных

| Команда из корня SORB | Действие |
| --- | --- |
| `npm run db:up` | Запустить PostgreSQL и дождаться готовности |
| `npm run db:deploy` | Применить уже сохраненные миграции |
| `npm run db:migrate` | Создать и применить миграцию после изменения схемы |
| `npm run db:studio` | Запустить Prisma Studio для просмотра и редактирования данных |
| `npm run db:logs` | Смотреть логи базы |
| `npm run db:check -w backend` | Проверить подключение и таблицу пользователей |
| `npm run prisma:generate -w backend` | Повторно сгенерировать Prisma Client |
| `npm run prisma:validate -w backend` | Проверить корректность схемы Prisma |

Схема находится в `backend/prisma/schema.prisma`, история миграций —
в `backend/prisma/migrations/`. Для изменения схемы в процессе разработки:

1. Измените `schema.prisma`.
2. Выполните `npm run db:migrate` и введите понятное имя миграции.
3. Выполните `npm run prisma:generate -w backend`.
4. Добавьте измененную схему и новую миграцию в Git вместе с кодом.

В Prisma 7 генерацию клиента после изменения схемы выполняйте явно.
Для команды с заданным именем миграции в Windows используйте `npm.cmd`, чтобы
PowerShell корректно передал параметры после `--`:

```powershell
npm.cmd run prisma:migrate --workspace backend -- --name add_resources
```

Остановка контейнеров не удаляет данные. Не добавляйте `-v` к `docker compose down`
при обычной остановке: этот параметр удаляет volume с базой.
Смену пароля в Compose для уже созданного volume нужно согласовать с изменением
пароля пользователя внутри PostgreSQL; изменение переменной не переинициализирует существующую БД.

## Проверки и сборка

Все команды выполняются из корня SORB после установки зависимостей:

```powershell
npm run typecheck                 # Проверка типов backend и frontend
npm run lint                      # ESLint для frontend
npm test                          # Тесты backend
npm run build                     # Сборка обеих частей
npm run prisma:validate -w backend # Проверка схемы базы
npm run db:check -w backend        # Проверка работающей базы после миграций
```

Текущие тесты проверяют `/health`, CORS, ответы `/ready` и OpenAPI. Обращения
к базе в тестах готовности подменяются; работающий PostgreSQL не требуется,
но необходим файл `backend/.env`. Команда `db:check` требует запущенную базу
и примененные миграции.

Результаты сборки: `backend/dist/` и `frontend/dist/`.
Чтобы проверить собранное приложение локально, сначала остановите режим разработки.
В двух терминалах из корня SORB выполните:

```powershell
# API из скомпилированного JavaScript; PostgreSQL должен быть запущен.
npm start -w backend
```

```powershell
# Предпросмотр сборки frontend на том же origin, что и в конфигурации API.
npm.cmd run preview --workspace frontend -- --host 127.0.0.1 --port 5173 --strictPort
```

Откройте `http://localhost:5173`. Предпросмотр Vite предназначен для проверки сборки.

## Обновление проекта

Остановите `npm run dev` и сохраните свои изменения перед получением нового кода.
Если ваша ветка допускает обновление без слияния:

```powershell
git pull --ff-only
npm ci
npm run db:up
npm run db:deploy
npm run dev
```

Если Git сообщает, что обновление невозможно, сначала разберите состояние ветки
и локальные изменения. Существующие `.env` повторно не копируйте. Если появились
новые настройки в `.env.example`, добавьте их вручную в свой `.env`.

Для полностью контейнерного запуска после обновления исходников выполните:

```powershell
docker compose --profile app up -d --build --wait
```

## Решение типичных ошибок

### `node`, `npm`, `git` или `docker` не распознается

Проверьте установку нужной программы. Закройте и снова откройте терминал после
установки, чтобы обновился `PATH`. Проверьте версию соответствующей командой
из раздела установки инструментов.

### PowerShell запрещает запуск `npm.ps1`

Используйте `npm.cmd` вместо `npm`, например:

```powershell
npm.cmd ci
npm.cmd run dev
```

Это позволяет пользоваться npm без изменения политики выполнения PowerShell.

### `EBADENGINE` или неподдерживаемая версия Node.js

Проверьте `node --version` и установите поддерживаемую ветку Node.js из раздела
требований. Затем откройте новый терминал и повторите `npm ci`.

### Docker не может подключиться к движку / отсутствует `docker_engine`

Запустите Docker Desktop, дождитесь готовности и проверьте `docker info`.
Убедитесь, что выбраны Linux-контейнеры. После этого повторите `npm run db:up`.

### Не задана `DATABASE_URL` при установке или генерации Prisma

Создайте `backend/.env` из `backend/.env.example` до запуска `npm ci`.
Проверьте наличие строки `DATABASE_URL` и повторите команду.

### Prisma не подключается к PostgreSQL / `/ready` возвращает 503

Проверьте состояние контейнера и его логи:

```powershell
docker compose ps
npm run db:logs
```

Для локального API в `DATABASE_URL` должны быть `localhost:5433`, имя базы `sorb`
и учетные данные из Compose. Адрес `db:5432` работает внутри Docker-сети.
После исправления `.env` перезапустите API.

### Таблица `User` не существует

База запущена, но миграции еще не применены:

```powershell
npm run db:deploy
npm run db:check -w backend
```

### `P1002` при ожидании advisory lock во время миграции

Проверьте, не выполняется ли другая миграция в соседнем терминале. Завершите ее
или отмените через `Ctrl+C`, затем повторите команду. Не запускайте несколько
команд миграции одновременно и не сбрасывайте базу для снятия блокировки.

### Порт занят / `EADDRINUSE` / Vite сообщает о занятом 5173

Остановите прежний `npm run dev`, отдельные процессы API/frontend или полную
Docker-конфигурацию, которая использует эти порты. Если меняете порт, согласованно
обновите настройки API, frontend и CORS. При изменении порта базы поменяйте
публикуемый порт в Compose и `DATABASE_URL` локального API.

### На странице написано «API недоступен» или возникает CORS-ошибка

Откройте `/health` и проверьте сообщения в терминале API. Убедитесь, что
`VITE_API_URL` указывает на работающий сервер. Открывайте frontend по адресу
`http://localhost:5173`, который указан в `CORS_ORIGIN`. После изменения окружения
перезапустите оба процесса.

### Не найден Windows-бинарник esbuild или другой платформенный пакет

Остановите процессы разработки, затем переустановите зависимости с optional-пакетами:

```powershell
npm ci --include=optional
```

Дождитесь завершения установки и повторите `npm run dev`. Не используйте
`--ignore-scripts` или `--omit=optional` для локальной установки: нужны генерация
Prisma Client и платформенные бинарники инструментов.

### `npm ci` сообщает о несовпадении `package.json` и lock-файла

Убедитесь, что получили оба файла из одной версии проекта. Если вы сами изменили
зависимости, выполните `npm install` и сохраните измененные `package.json`
и `package-lock.json` вместе. При обычной установке не удаляйте lock-файл:
он обеспечивает воспроизводимый набор версий.

### Ошибка скачивания пакетов npm или образов Docker

Проверьте интернет-соединение, настройки прокси/VPN и доступ к npm registry
или реестру Docker. После восстановления доступа повторите установку или запуск.
